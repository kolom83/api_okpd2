# Описание модели OKPD2 и скрипта okpd_predict_cli_file_1.py
## Документ для службы безопасности

---

## 1. Назначение

Модель `okpd_model.pkl` и скрипт `okpd_predict_cli_file_1.py` предназначены для автоматического определения кодов ОКПД2 по наименованию продукции (электроника, радиотехника) при интеграции с 1С.

---

## 2. Технология работы модели

### 2.1. Структура модели (okpd_model.pkl)
Модель представляет собой pickle-файл (~5.4 МБ), содержащий:
- **vectorizer** — векторизатор текста (TfidfVectorizer) для преобразования названий в числовые векторы
- **knn_model** — модель k-ближайших соседей (KNeighborsClassifier) для поиска аналогов
- **registry_df / train_df** — датафреймы с реестром продукции и обучающими данными
- **okpd2_frequencies** — частоты встречаемости кодов ОКПД2 в реестре
- **valid_okpd2** — список допустимых кодов ОКПД2

### 2.2. Алгоритм предсказания
1. Входное наименование товара векторизуется через TfidfVectorizer
2. KNN-модель находит 5 ближайших аналогов в реестре
3. Применяется взвешенное голосование по схожести (similarity = 1 - distance)
4. При ничьей выбирается код с наибольшей частотой в реестре
5. Рассчитывается confidence (уверенность) как доля лучшего scores от суммы всех scores
6. Результат возвращается в формате JSON

---

## 3. Скрипт okpd_predict_cli_file_1.py

### 3.1. Назначение
CLI-скрипт для вызова модели из 1С через командную строку.

### 3.2. Синтаксис запуска
```bash
python okpd_predict_cli_file_1.py "Товар1" "Товар2" -o результат.json [-t порог] [-m модель] [-v]
```

**Параметры:**
- `products` — одно или несколько названий товаров (обязательно)
- `-o, --output` — путь к файлу для вывода JSON (обязательно для 1С)
- `-t, --threshold` — порог уверенности (по умолчанию: 0.7)
- `-m, --model` — путь к файлу модели (по умолчанию: okpd_model.pkl)
- `-v, --verbose` — вывод логов в stderr

### 3.3. Формат выходных данных (JSON)
```json
{
  "total": 2,
  "predictions": [
    {
      "product_name": "Ноутбук",
      "predicted_okpd2": "26.40.33.190",
      "confidence": 0.85,
      "status": "SUCCESS",
      "similar_product": "...",
      "similarity": 0.92,
      "warning": null,
      "top_5_matches": [...]
    }
  ]
}
```

**Статусы:**
- `SUCCESS` — уверенность ≥ порога
- `LOW_CONFIDENCE` — уверенность < порога
- `ERROR` — ошибка обработки

### 3.4. Коды возврата
- `0` — все предсказания успешны
- `1` — есть предупреждения (LOW_CONFIDENCE)
- `2` — есть ошибки (ERROR, файл модели не найден)
- `3` — ошибка записи файла результата

## 5. Безопасность

### 5.1. Особенности реализации
- Модель загружается через `pickle.load()` — **доверяйте только проверенным .pkl файлам**
- Скрипт не выполняет сетевых запросов
- Скрипт не использует динамическое выполнение кода (eval, exec)
- Все входные данные обрабатываются как строки
- Вывод результатов только в файл и stderr

### 5.2. Рекомендации
1. Размещать модель и скрипт в защищённой директории сервера 1С
2. Ограничить права доступа к файлу модели (только чтение для пользователя 1С)
3. Использовать актуальные версии библиотек для получения исправлений безопасности
4. Валидировать входящие названия товаров на стороне 1С перед передачей в скрипт
